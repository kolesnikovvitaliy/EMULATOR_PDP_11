# 📦 Модуль Управления Динамическими Буферами: `mem_byte.h`

[![C Version](https://shields.io)](https://wikipedia.org)
[![License](https://shields.io)](https://opensource.org)
[![Memory Safety](https://shields.io)]()

Современный, безопасный и инкапсулированный интерфейс на языке C для работы с динамическими байтовыми массивами в куче (heap). Модуль спроектирован с использованием паттерна **Opaque Object (Непрозрачный объект)**, что полностью исключает случайную порчу метаданных буфера из пользовательского кода.

---

## 🚀 Ключевые Особенности

*   **Полная инкапсуляция:** Внутреннее устройство структуры (размер, емкость, выравнивание) скрыто в файле реализации (`.c`).
*   **Двухэтапная инициализация:** Разделение аллокации управляющего дескриптора и целевого буфера данных для гибкого контроля памяти.
*   **Защита от утечек:** Каскадное автоматическое освобождение всех связанных ресурсов при уничтожении объекта.
*   **Устойчивость к NULL:** Безопасная обработка нулевых указателей при очистке памяти.

---

## 🛠 Подробное Описание API Функций

### 1. `mem_byte_new`

```c
struct mem_byte_t *mem_byte_new();
```

#### 📋 Описание
Создает и аллоцирует в куче новый экземпляр управляющего дескриптора буфера. Функция выделяет память строго под метаданные (`struct mem_byte_t`). Внутренний указатель на целевой массив байт при этом инициализируется как `NULL`.

#### 📊 Параметры
*Функция не принимает аргументов.*

#### ↩️ Возвращаемые значения
*   `struct mem_byte_t*` — Успешно. Указатель на созданный объект управления.
*   `NULL` — Ошибка. Не удалось выделить память в куче (системный `malloc` вернул `NULL`).

#### ⚠️ Важное замечание
Выделенная память должна быть обязательно освобождена функцией `mem_byte_destroy` во избежание утечек памяти.

---

### 2. `mem_byte_create`

```c
void mem_byte_create(struct mem_byte_t *self, const size_byte_buffer size);
```

#### 📋 Описание
Производит фактическое выделение непрерывного массива байт в куче на основании переданного размера `size`. Функция связывает выделенную область памяти с ранее созданным дескриптором `self`.

#### 📊 Параметры
*   `[in,out] self` — Указатель на структуру управления буфером, полученный из функции `mem_byte_new`.
*   `[in] size` — Количество выделяемых байт. Тип данных `size_byte_buffer` определяется внешним заголовочным файлом `types/types.h`.

#### 🚨 Предупреждения (Undefined Behavior)
Поведение программы не предсказуемо, если:
1. Передан указатель `self` равный `NULL`.
2. Объект `self` уже был инициализирован ранее (повторный вызов `mem_byte_create`).

---

### 3. `mem_byte_destroy`

```c
void mem_byte_destroy(struct mem_byte_t *self);
```

#### 📋 Описание
Каскадно освобождает всю память, связанную с объектом. Сначала уничтожается внутренний рабочий массив байт (если он был создан), затем освобождается сам дескриптор `mem_byte_t`.

#### 📊 Параметры
*   `[in,out] self` — Указатель на уничтожаемый объект буфера.

#### 🛡 Безопасность
Если в функцию передан `NULL`, она завершает работу **безопасно**, не вызывая аварийного завершения программы (Segmentation Fault).

#### 💡 Рекомендация по использованию
После вызова функции ваш указатель становится «висячим» (Dangling Pointer). Настоятельно рекомендуется вручную занулить его сразу после вызова:
```c
mem_byte_destroy(my_buffer);
my_buffer = NULL; // Защита от Double Free
```

## 💻 Пример Использования

Полный цикл жизни динамического буфера: от создания до безопасного уничтожения.

```c
#include <stdio.h>
#include "mem_byte.h"

int main(void) {
    // Шаг 1: Выделяем дескриптор управления
    struct mem_byte_t *buffer_manager = mem_byte_new();

    if (buffer_manager == NULL) {
        fprintf(stderr, "Критическая ошибка: Не удалось выделить память под дескриптор!\n");
        return 1;
    }

    // Шаг 2: Выделяем целевой буфер данных размером 1024 байта
    const size_byte_buffer pool_size = 1024;
    mem_byte_create(buffer_manager, pool_size);

    printf("Буфер успешно создан и готов к работе.\n");

    /* ... Здесь происходит работа с буфером через функции модуля ... */

    // Шаг 3: Полная очистка ресурсов
    mem_byte_destroy(buffer_manager);
    buffer_manager = NULL; // Зануляем для безопасности

    printf("Память успешно очищена.\n");
    return 0;
}
```

## 🏗 Архитектурная Схема Компонента

Структура `mem_byte_t` объединяет низкоуровневый буфер данных и **VMT (Virtual Method Table / Таблицу виртуальных методов)**, что позволяет эмулировать как обычное ОЗУ, так и MMIO (Memory-Mapped I/O — регистры периферийных устройств):

┌────────────────────────────────────────────────────────┐
│                      mem_byte_t                        │
└────────────────────────────────────────────────────────┘
│
│▼
[ Данные и Границы ]
▼ [ Таблица Методов (VMT) ]
┌─────────────────────────────────┐
┌─────────────────────────────────┐
│  byte_t *buf_b ───────────────┐ │
│  read_byte_t  read_byte         │
│  (Сырой массив байт в ОЗУ)    │ │
│  (Чтение 8-бит из ячейки)       │
│                               ▼ │
├─────────────────────────────────┤
│  [0x0000] [0x0001] ... [size]   │
│  write_byte_t write_byte        │
├─────────────────────────────────┤
│  (Запись 8-бит в ячейку)        │
│  size_byte_buffer size_b        │
├─────────────────────────────────┤
│  (Лимит адресного пространства) │
│  read_word_t  read_word         │
└─────────────────────────────────┘
│  (Чтение 16-бит / Четный адрес) │
├─────────────────────────────────┤
│  write_word_t write_word        │
│  (Запись 16-бит / Четный адрес) │
└─────────────────────────────────┘

## 📐 Детальное Описание Полей Структуры `mem_byte_t`

### 1. `buf_b`
```c
byte_t *buf_b;
```
*   **Тип:** Указатель на сырой динамический массив байт (`byte_t`).
*   **Описание:** Выделенный в куче хост-машины физический буфер. Он симулирует реальное адресное пространство ретро-компьютера PDP-11, его отдельный банк памяти, страницу MMU или ПЗУ.

### 2. `size_b`
```c
size_byte_buffer size_b;
```
*   **Тип:** Ограничитель размера (`size_byte_buffer`), определяемый в `types/types.h`.
*   **Описание:** Фактический размер выделенного буфера в байтах. Используется функциями чтения/записи для аппаратного контроля границ (Bound Checking). В случае выхода за лимит генерируются внутренние исключения шины или аварийные сигналы процессора.

### 3. `read_byte`
```c
read_byte_t read_byte;
```
*   **Сигнатура:** `byte_t (*read_byte)(const mem_byte_t *self, uint16_t addr);`
*   **Описание:** Указатель на функцию низкоуровневого чтения одного байта (8 бит).
*   **Аргументы:** Принимает указатель на себя (`self`) и относительный/физический адрес ячейки памяти (`addr`).
*   **Возврат:** Возвращает считанное 8-битное значение.

### 4. `write_byte`
```c
write_byte_t write_byte;
```
*   **Сигнатура:** `void (*write_byte)(mem_byte_t *self, uint16_t addr, byte_t val);`
*   **Описание:** Указатель на функцию низкоуровневой записи одного байта (8 бит).
*   **Аргументы:** Модифицируемый объект (`self`), адрес назначения (`addr`) и записываемое байтовое значение (`val`).

### 5. `read_word`
```c
read_word_t read_word;
```
*   **Сигнатура:** `word_t (*read_word)(const mem_byte_t *self, uint16_t addr);`
*   **Описание:** Указатель на функцию низкоуровневого чтения одного машинного слова (16 бит).
*   **⚠️ Специфика PDP-11:** Архитектура требует, чтобы доступ к словам осуществлялся **строго по четным адресам** (`addr % 2 == 0`). Обработка нечетного адреса внутри этой функции должна вызывать аппаратное прерывание процессора (Trap / Ошибка шины).

### 6. `write_word`
```c
write_word_t write_word;
```
*   **Сигнатура:** `void (*write_word)(mem_byte_t *self, uint16_t addr, word_t val);`
*   **Описание:** Указатель на функцию низкоуровневой записи одного машинного слова (16 бит).
*   **⚠️ Специфика PDP-11:** Попытка записи слова по нечетному адресу является критическим нарушением выравнивания. Логика функции обязана перехватывать такие запросы и генерировать системную ошибку процессора (Trap-ошибка выравнивания).

## 🛠 Пример Внутренней Реализации Полиморфизма

Ниже показано, как разработчик подсистемы памяти может инициализировать структуру `mem_byte_t` разными указателями для стандартного ОЗУ и кастомного устройства (например, регистра статуса терминала):

```c
#include "pdp_11/memory/mem_byte_p.h"

// --- Реализация для стандартного ОЗУ ---
byte_t ram_read_byte(const mem_byte_t *self, uint16_t addr) {
    return self->buf_b[addr]; // Прямое чтение из буфера
}

void ram_write_byte(mem_byte_t *self, uint16_t addr, byte_t val) {
    self->buf_b[addr] = val; // Прямая запись в буфер
}

// --- Реализация для регистров ввода-вывода (MMIO) ---
byte_t mmio_read_byte(const mem_byte_t *self, uint16_t addr) {
    // Чтение регистра может очистить флаги готовности периферии
    printf("Лог: Чтение регистра MMIO по адресу 0x%04X\n", addr);
    return self->buf_b[addr];
}

// --- Функция сборки фабрики памяти ---
void init_ram_bank(mem_byte_t *mem, size_byte_buffer size) {
    mem->buf_b = malloc(size);
    mem->size_b = size;

    // Инициализируем таблицу виртуальных методов
    mem->read_byte  = ram_read_byte;
    mem->write_byte = ram_write_byte;
    // ... аналогично для read_word и write_word с проверкой четности
}
```
