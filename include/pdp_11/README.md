# 🏛️ Архитектура Заголовочных Файлов (Include) Эмулятора PDP-11

[![Language](https://shields.io)](https://wikipedia.org)
[![Standard](https://shields.io)](#)
[![Component](https://shields.io)](#)

Данный документ содержит исчерпывающее техническое описание структуры, назначения и внутренней логики всех интерфейсных и внутренних заголовочных файлов, расположенных в директории `include/pdp_11/`. Проект спроектирован по канонам модульной низкоуровневой эмуляции вычислительных систем, изолируя подсистемы памяти, регистров, декодирования команд и периферийного ввода-вывода (MMIO).

---

## 🗺️ Карта Директории `include/pdp_11/`

```text
📂 include/pdp_11/
├── 📄 pdp_11.h            # Открытый интерфейс (Public API) эмулятора
├── 📄 pdp_11_p.h          # Приватные структуры ядра (Private Core)
├── 📄 run.h               # Контроллер жизненного цикла и тактов CPU
│
├── 📂 command/            # Подсистема декодирования и АЛУ
│   └── [Файлы декодера, масок инструкций и исполнения команд]
│
├── 📂 register/           # Подсистема регистрового файла и флагов
│   └── [Файлы управления R0-R7 и регистром состояния PSW]
│
├── 📂 memory/             # Подсистема подсистемы ОЗУ и виртуальных адресов
│   └── [Файлы работы с шиной, проверки четности и переполнения]
│
└── 📂 device_io/          # Подсистема Memory-Mapped I/O (MMIO)
    └── [Файлы диспетчеризации адресов страницы ввода-вывода]
```

## 📑 Детальное Анатомическое Описание Компонентов

### 1. 🔑 Корневые интерфейсные файлы ядра

#### 📄 `include/pdp_11/pdp_11.h` (Public Facade)
*   **Архитектурная роль:** Главная точка входа для внешних модулей, графических оболочек или систем тестирования. Скрывает реализацию и предоставляет только чистый интерфейс.
*   **Основные задачи:**
    *   Глобальная инициализация и аллокация структур виртуальной машины.
    *   Предоставление функций управления питанием (`INIT`, `RESET`).
    *   Экспорт сигнальных функций для перехвата состояния эмулятора снаружи.

#### 📄 `include/pdp_11/pdp_11_p.h` (Private Implementation)
*   **Архитектурная роль:** Закрытый заголовочный файл (Private Header), содержащий внутренние структуры данных. Сюда инкапсулировано реальное «железо».
*   **Основные задачи:**
    *   Описание структуры `CPU_State` (массив регистров, флаги, счетчики тактов).
    *   Описание структуры `Bus_State` для эмуляции шин UNIBUS/Q-BUS.
    *   Объявление внутренних макросов для манипуляции битами слов (Byte Swapping, Sign Extension).


#### 📄 `include/pdp_11/run.h` (Execution Machine)
*   **Архитектурная роль:** Диспетчер главного цикла процессора (Main Execution Loop).
*   **Основные задачи:**
    *   Управление состояниями процессора (`RUNNING`, `HALTED`, `WAITING`).
    *   Синхронизация тактовой частоты (эмуляция задержек инструкций).

### 2. 📂 Специализированные Подсистемы (Subsystems)

#### 📂 Директория `include/pdp_11/command/` (Декодер и Инструкции)
Данный модуль отвечает за разбор бинарных опкодов команд Macro-11 и распределение их на потоки исполнения.
*   **Функционал подсистемы:**
    *   Парсинг 16-битных инструкций для выделения полей: *Код операции (Opcode)*, *Режим адресации источника/приемника*, *Номера регистров*.
    *   Реализация 8 классических режимов адресации PDP-11 (Прямой, Косвенный, Автоинкрементный, Автодекрементный, Индексный и их отложенные формы).

#### 📂 Директория `include/pdp_11/register/` (Регистровый файл и PSW)
Обеспечивает изоляцию и быструю работу со внутренними регистрами общего назначения (РОН) процессора и флагами ветвления.
*   **Функционал подсистемы:**
    *   Предоставление доступа к регистрам `R0-R5`.
    *   Эмуляция Указателя Стека `SP` (`R6`) и Счетчика Команд `PC` (`R7`).
    *   Управление регистром состояния процессора `PSW` (Processor Status Word), содержащим флаги `N` (отрицательно), `Z` (ноль), `V` (переполнение), `C` (перенос).


#### 📂 Директория `include/pdp_11/memory/` (Шина и Оперативная память)
Эмулирует физическое адресное пространство. Отвечает за безопасное чтение и запись данных, предотвращая рассинхронизацию шины.
*   **Функционал подсистемы:**
    *   Выделение и управление массивом виртуальной памяти (базовые 64 КБ для 16-битной адресации).
    *   Строгий контроль выравнивания границ слов: обращение к Word по нечетному адресу немедленно вызывает прерывание шины.
    *   Интеграция со страницей ввода-вывода (IO Page).


#### 📂 Директория `include/pdp_11/device_io/` (Memory-Mapped I/O)
Реализует концепцию PDP-11, где внешние устройства управляются через чтение/запись в выделенные адреса оперативной памяти.
*   **Функционал подсистемы:**
    *   Перехват запросов чтения/записи в верхнем диапазоне адресов ОЗУ (`0176000` — `0177777` в восьмеричной системе).
    *   Эмуляция системного терминала (регистры статуса/данных клавиатуры `RKS`/`RKB` и дисплея `TKS`/`TKB`).
    *   Перенаправление потоков данных в консоль хост-машины.

## 📈 Конвейер Взаимодействия Подсистем (Data Flow)

Каждый раз, когда функция `pdp11_step()` из `run.h` производит итерацию, подсистемы общаются по следующему строгому протоколу:

```text
       [  pdp11_step()  ]  (Вызывается главным циклом)
               │
               ▼
   1. 📂 memory & register ──> [ cmd_fetch() ] Извлекает опкод, двигает PC (R7)
               │
               ▼
   2. 📂 command           ──> [ cmd_decode() ] Разбирает биты, определяет типы
               │
               ▼
   3. 📂 command & memory  ──> [ cmd_resolve_address() ] Вычисляет адреса операндов
               │
               ▼
   4. 📂 device_io/memory  ──> Чтение/Запись данных (если адрес MMIO -> уходит в device_io)
               │
               ▼
   5. 📂 register (PSW)    ──> Обновление флагов АЛУ (N, Z, V, C) по итогу операции
```

## ⚙️ Правила Разработки и Расширения (Для разработчиков)

1.  **Принцип Изоляции:** Запрещено вызывать функции из `include/pdp_11/command/` внутри подсистемы `memory`. Память ничего не знает об инструкциях, она лишь хранит и отдает байты.
2.  **Восьмеричная Система:** При добавлении масок или констант в файлы конфигурации, используйте префиксы или комментарии в традиционной для PDP-11 **восьмеричной (octal)** системе счисления (например, адрес `0177564`).
3.  **Потокобезопасность:** Все структуры внутри `pdp_11_p.h` должны модифицироваться монопольно в рамках одного потока эмуляции CPU для предотвращения состояния гонки (Race Condition) при эмуляции асинхронных прерываний периферии.
